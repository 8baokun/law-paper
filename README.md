# 应用法学论文写作专家团·总览

## 架构

本专家团由8个独立技能组成，覆盖应用法学论文写作完整生产线的七个环节。

### 论文生产线七环节模型

```
环节1：选题检查        → paper-topic-validator
环节2：思路梳理        → paper-idea-architect
环节3：提纲审查        → paper-outline-reviewer
环节4：查资料          → paper-literature-coordinator
环节5：专门写          → paper-writing-engine
环节6：写后核验        → paper-argument-evaluator
环节7：文风处理        → de-ai-polish
```

### 元认知层

```
systems-thinking（系统思维）——横跨所有环节的元认知工具
可在任何环节被调用来诊断当前方案/流程/文档的结构合理性
```

## 七环节详细说明

### 环节1：选题检查（paper-topic-validator）

**输入**：论文选题设想  
**输出**：选题诊断报告  
**五维评估**：问题意识清晰度、学术增量空间、论证可行性、规范分析深度、实践关联度  
**通过条件**：五维综合评分 ≥ 3.5  
**回退条件**：综合评分 < 3.5 → 修改选题后重新提交

### 环节2：思路梳理（paper-idea-architect）

**输入**：环节1的选题诊断报告（通过的选题）  
**输出**：标准化论证框架文档  
**核心流程**：核心命题凝练→论证线索梳理→前置论点检验→依据类型标注→反驳预判→章节规划  
**数据接口**：标准化论证框架文档是环节3（提纲审查）的输入  
**回退条件**：核心命题无法凝练为一句话 → 回退到环节1

### 环节3：提纲审查（paper-outline-reviewer）

**输入**：环节2的标准化论证框架文档 + 正式提纲  
**输出**：提纲审查报告  
**八项检查**：逻辑结构、论证层次、规范分析、案例支撑、文献覆盖、问题回应闭环、篇幅分配、创新点呈现  
**数据接口对齐**：提纲须与环节2的论证线索一致，否则标记"数据接口不对齐"  
**回退条件**：提纲与论证框架不对齐 → 回退到环节2

### 环节4：查资料（paper-literature-coordinator）

**输入**：环节3通过的提纲  
**输出**：标准化文献清单 + 阅读笔记  
**四类文献**：学理文献、规范文献、案例文献、比较法文献  
**与法律实务检索的区别**：面向学术论证和学术对话，关注文献谱系、增量空间识别、引用策略规划  
**回退条件**：某前置论点文献覆盖不足 → 扩大检索后重新评估

### 环节5：专门写（paper-writing-engine）

**输入**：环节3通过的提纲 + 环节4的文献清单  
**输出**：论文初稿（Markdown格式）  
**四种结构模式**：制度分析型、规范解释型、实证研究型、比较法研究型  
**法学专门指导**：规范分析方法、案例分析框架、比较法研究范式、法学引注规范（依据《法学引注手册》2019年版，覆盖法条/案例/学说/比较法四大类）  
**回退条件**：写作中发现文献不足 → 回退到环节4；发现框架问题 → 回退到环节2

### 环节6：写后核验（paper-argument-evaluator）

**输入**：环节5的论文初稿  
**输出**：论文学证强度评估报告（投稿场景）  
**六维评估**：法源支撑充分性(0.20)、实证/案例基础充分性(0.20)、论证逻辑严密性(0.25)、学术对话能力(0.20)、司法实践关联度(0.10)、学术增量贡献度(0.20)  
**否决规则**：10条（原版5条 + 投稿场景5条，含引注格式严重缺陷否决）  
**审稿人预判**：预判最可能的质疑和最强反驳  
**回退条件**：综合评分 < 3.0 → 回退到环节5；增量缺失 → 回退到环节2  
**快速通道**：上游评分≥4.5可简化，但环节6不可跳过

### 环节7：文风处理（de-ai-polish）

**输入**：环节6通过的论文初稿  
**输出**：去AI腔后的终稿  
**检测规则**：8大类18条（对比句式、程式化连接词、结尾姿态句、口语化表述、绝对化表述、工整排比、学术自我指涉、标签式概括）  
**两种模式**：detect（检测）和fix（修改）  
**论文适配**：区分论文中的合理使用（不应去除）和高发AI痕迹（重点检测）  
**回退条件**：发现实质性内容问题 → 回退到环节5

## 回溯协议

```
环节1（选题检查）不通过 → 修改选题后重新提交检查
环节2（思路梳理）核心命题无法凝练 → 回退到环节1（选题检查）
环节3（提纲审查）不通过 → 回退到环节2（思路梳理）
环节4（查资料）文献覆盖不足 → 扩大检索后重新评估
环节5（专门写）发现文献不足 → 回退到环节4（查资料）
环节5（专门写）发现框架问题 → 回退到环节2（思路梳理）
环节6（写后核验）综合评分 < 3.0 → 回退到环节5（专门写）
环节6（写后核验）增量缺失 → 回退到环节2（思路梳理）
环节6（写后核验）法源错误 → 回退到环节4（查资料）
环节6（写后核验）引注格式严重缺陷 → 回退到环节5（专门写）
环节7（文风处理）发现实质问题 → 回退到环节5（专门写）
```

## 快速通道

```
上游环节评分 ≥ 4.5/5.0 → 下游环节启用简化模式
但环节6和环节7不可跳过
```

## 数据接口

```
环节1输出 → 选题诊断报告
环节2输出 → 标准化论证框架文档（环节3的输入）
环节3输出 → 提纲审查报告
环节4输出 → 标准化文献清单 + 阅读笔记（环节5的输入）
环节5输出 → 论文初稿（Markdown格式）
环节6输出 → 论文学证强度评估报告
环节7输出 → 去AI腔后的终稿
```

## 使用方式

### 完整生产线模式

按环节1→2→3→4→5→6→7的顺序依次执行。每个环节通过后进入下一个，不通过则按回溯协议退回。

### 单环节使用

每个技能可独立使用，不依赖完整生产线。例如：

- 只想检查选题→调用paper-topic-validator
- 只想梳理思路→调用paper-idea-architect
- 只想审查提纲→调用paper-outline-reviewer
- 只想系统检索文献→调用paper-literature-coordinator
- 只想撰写论文→调用paper-writing-engine
- 只想核验论证强度→调用paper-argument-evaluator
- 只想去AI腔→调用de-ai-polish
- 想审视方案结构→调用systems-thinking

### 元认知介入

systems-thinking可在任何环节被调用来诊断当前方案/流程/文档的结构合理性。其六维框架（整体性分析、耦合关系、涌现性、反馈回路、盲区扫描、边界条件）可用于：

- 诊断论文论证框架的结构合理性
- 检查环节之间的数据接口是否对齐
- 扫描论证盲区和隐含假设
- 评估回溯决策的合理性

- 项目级：`[workspace]/.workbuddy/skills/`
