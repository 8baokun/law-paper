# 应用法学论文写作专家团·总览

## ⚠️ 学术伦理声明

**本专家团是研究辅助工具，不替代作者。** 使用前请务必阅读 [学术伦理声明.md](学术伦理声明.md)。

三条红线：
- **不可替代原创**——核心观点、论证框架、学术判断由作者本人完成
- **不可编造文献**——所有文献线索必须亲自核实原文后才能引用
- **不可代写全文**——写作产出须实质性审查和修改，不得直接提交

使用本工具产出的任何学术成果，学术道德责任由作者本人承担。

## 定位：产学研一体化的通用法学论文框架

本专家团是一个**通用法学论文写作框架**，以应用法学为主、理论法学为辅，覆盖论文写作完整生产线。

核心理念：**论文的起点是解决问题。** 默认形态能发期刊论文，降级形态能供日常实务参考，整体是一个可微调的通用框架——不走极端，不绑死单一场景。

### 三层架构

| 层级 | 内容 | 定位 |
|------|------|------|
| **第一层：通用核心** | 七环节完整生产线，所有论文必经 | 学研标准，默认配置 |
| **第二层：实务增强模块** | 模块A实务溯源、模块B可落地性评估、模块C法律生态审查 | 可选加载，按需启用 |
| **第三层：使用场景预设** | 学研标准/实务应用/决策参考/自定义 | 一键切换，免去逐项配置 |

详细配置说明见 [预设配置说明.md](预设配置说明.md)。

## 架构

本专家团由9个独立技能组成，覆盖法学论文写作完整生产线的七个环节+元认知层+实务审查层。

### 论文生产线七环节模型

```
环节1：选题检查        → paper-topic-validator

环节6：写后核验        → paper-argument-evaluator
环节7：文风处理        → de-ai-polish
```

### 实务审查层（可选）

```
环节8：法律生态审查    → legal-ecology-reviewer（模块C，可选加载）
```

### 元认知层

```
systems-thinking（系统思维）——横跨所有环节的元认知工具
可在任何环节被调用来诊断当前方案/流程/文档的结构合理性
```

## 七环节详细说明

### 环节1：选题检查（paper-topic-validator）

**输入**：论文选题设想  
**输出**：选题诊断报告 + 选题文献综述报告  
**五维评估**：问题意识清晰度、学术增量空间、论证可行性、规范分析深度、实践关联度  
**选题验证型文献综述**：5-15篇核心文献定向综述，验证选题意义，为维度2提供文献证据。与环节4系统化检索分工：环节1验证"值不值得做"，环节4解决"怎么写"  
**检索工具链**：集成paper-harvester——NCPSSD（主力中文源，单词查询）+ OpenAlex（比较法素材）+ WebSearch（实务/学位论文补充），多源去重合并  
**核心文献下载**：筛选出的5-15篇核心文献尝试下载PDF到 `[论文项目目录]/papers/`，付费墙文献不下载但记录论文名/作者/期刊/年份等核心信息供人工获取。反爬保护：间隔≥3秒，会话上限15篇，连续失败3次暂停  
**可选模块A**：实务问题溯源（实务轨启用，增加"实务痛点真实性"维度，学术增量降权）  
**通过条件**：五维综合评分 ≥ 3.5  
**回退条件**：综合评分 < 3.5 → 修改选题后重新提交检查

### 环节2：思路梳理（paper-idea-architect）

**输入**：环节1的选题诊断报告（通过的选题）  
**输出**：标准化论证框架文档  
**核心流程**：核心命题凝练→论证线索梳理→前置论点检验→依据类型标注→反驳预判→章节规划  
**实务轨提示**：需额外标注"实务痛点锚点"——明确论证框架回应的是哪个实务问题  
**数据接口**：标准化论证框架文档是环节3（提纲审查）的输入  
**回退条件**：核心命题无法凝练为一句话 → 回退到环节1

### 环节3：提纲审查（paper-outline-reviewer）

**输入**：环节2的标准化论证框架文档 + 正式提纲  
**输出**：提纲审查报告  
**八项检查**：逻辑结构、论证层次、规范分析、案例支撑、文献覆盖、问题回应闭环、篇幅分配、创新点呈现  
**实务轨提示**：检查6"问题回应闭环"需额外核实——提纲是否回应了选题阶段标注的实务痛点  
**数据接口对齐**：提纲须与环节2的论证线索一致，否则标记"数据接口不对齐"  
**回退条件**：提纲与论证框架不对齐 → 回退到环节2

### 环节4：查资料（paper-literature-coordinator）

**输入**：环节3通过的提纲 + 环节1选题文献综述报告（作为检索起点）  
**输出**：标准化文献清单 + 阅读笔记  
**四类文献**：学理文献、规范文献、案例文献、比较法文献  
**检索工具链**：集成paper-harvester——NCPSSD（学理文献主力中文源，单词查询）+ OpenAlex/Crossref（比较法文献主力英文源）+ WebSearch（案例/实务/学位论文补充），多源去重合并  
**核心文献下载**：精读笔记环节的核心文献（每类3-5篇）按需下载PDF到 `[论文项目目录]/papers/`（与环节1共用），全部文献记录PDF链接和获取状态。付费墙文献不下载但记录核心信息供人工获取。反爬保护：间隔≥3秒，环节4会话上限15篇，连续失败3次暂停，下载前检查环节1是否已下载  
**实务轨提示**：增加"实务指引类文献"检索——裁判指引、操作规程、行政批复、行业合规指南等  
**与法律实务检索的区别**：面向学术论证和学术对话，关注文献谱系、增量空间识别、引用策略规划  
**回退条件**：某前置论点文献覆盖不足 → 扩大检索后重新评估

### 环节5：专门写（paper-writing-engine）

**输入**：环节3通过的提纲 + 环节4的文献清单  
**输出**：论文初稿（Markdown格式）  
**六种结构模式**：制度分析型、规范解释型、实证研究型、比较法研究型、问题对策型（实务轨推荐）、案例评析型（实务轨推荐）  
**法学专门指导**：规范分析方法、案例分析框架、比较法研究范式、法学引注规范（依据《法学引注手册》2019年版，覆盖法条/案例/学说/比较法四大类）  
**回退条件**：写作中发现文献不足 → 回退到环节4；发现框架问题 → 回退到环节2

### 环节6：写后核验（paper-argument-evaluator）

**输入**：环节5的论文初稿  
**输出**：论文学证强度评估报告（投稿场景）  
**六维评估**：法源支撑充分性(0.20)、实证/案例基础充分性(0.20)、论证逻辑严密性(0.25)、学术对话能力(0.20)、司法实践关联度(0.10)、学术增量贡献度(0.20)  
**可选模块B**：第七维度"实操建议可落地性"（论文含对策/建议时启用，权重重分配）  
**否决规则**：10条（原版5条 + 投稿场景5条，含引注格式严重缺陷否决）  
**审稿人预判**：预判最可能的质疑和最强反驳  
**回退条件**：综合评分 < 3.0 → 回退到环节5；增量缺失 → 回退到环节2  
**快速通道**：上游评分≥4.5可简化，但环节6不可跳过

### 环节7：文风处理（de-ai-polish）

**输入**：环节6通过的论文初稿  
**输出**：去AI腔后的终稿  
**检测规则**：8大类18条（对比句式、程式化连接词、结尾姿态句、口语化表述、绝对化表述、工整排比、学术自我指涉、标签式概括）  
**两种模式**：detect（检测）和fix（修改）  
**论文适配**：区分论文中的合理使用（不应去除）和高发AI痕迹（重点检测）  
**回退条件**：发现实质性内容问题 → 回退到环节5

### 环节8：法律生态审查（legal-ecology-reviewer）——可选

**输入**：环节7通过的终稿（含对策/建议部分）  
**输出**：法律生态可落地性审查报告  
**六项审查**：制度兼容性、主体可行性、程序可行性、资源可行性、政策兼容性、地域适配性  
**通过条件**：六项中至少四项通过，且无"制度兼容性"否决项  
**回退条件**：不通过 → 回退到环节5（重写建议部分）或环节2（重新梳理思路）  
**定位**：这不是"发表论文"的必经环节，而是"建议能否真正落地"的独立把关

## 使用方式

### 完整生产线模式

按环节1→2→3→4→5→6→7的顺序依次执行。每个环节通过后进入下一个，不通过则按回溯协议退回。

如选择"决策参考"预设，则在环节7后追加环节8（法律生态审查）。

### 单环节使用

每个技能可独立使用，不依赖完整生产线。例如：

- 只想检查选题→调用paper-topic-validator
- 只想梳理思路→调用paper-idea-architect
- 只想审查提纲→调用paper-outline-reviewer
- 只想系统检索文献→调用paper-literature-coordinator
- 只想撰写论文→调用paper-writing-engine
- 只想核验论证强度→调用paper-argument-evaluator
- 只想去AI腔→调用de-ai-polish
- 想审视方案结构→调用systems-thinking
- 想审查建议可落地性→调用legal-ecology-reviewer

### 元认知介入

systems-thinking可在任何环节被调用来诊断当前方案/流程/文档的结构合理性。其六维框架（整体性分析、耦合关系、涌现性、反馈回路、盲区扫描、边界条件）可用于：

- 诊断论文论证框架的结构合理性
- 检查环节之间的数据接口是否对齐
- 扫描论证盲区和隐含假设
- 评估回溯决策的合理性

## 🔧 领域适配

应用法学覆盖面广，不同领域的用词习惯、论证范式、引注规范均有差异。专家团默认以"通用法学论文"为基准，使用时应根据具体研究领域进行调整。

### 常见领域适配要点

| 领域 | 术语习惯 | 论证范式 | 引注特点 | 特殊注意 |
|------|---------|---------|---------|---------|
| 民商法 | 民法典条文引用密集 | 请求权基础分析、规范解释 | 侧重学理文献+司法解释 | 请求权竞合时说理要充分 |
| 刑法 | 罪刑法定原则贯穿 | 三阶层/四要件、法益分析 | 侧重法条+指导性案例 | 避免主观归罪，注意说理层次 |
| 行政法 | 联动行政诉讼法 | 合法性审查框架 | 侧重法律+行政法规 | 实务导向，关注制度运行效果 |
| 经济法 | 监管政策与法律并重 | 规范分析+实证研究 | 侧重政策文件+部门规章 | 注意政策时效性和效力层级 |
| 诉讼法 | 程序与实体交叉 | 程序正义论证 | 侧重法律+司法解释 | 注意程序细节，避免重实体轻程序 |
| 国际法 | 条约、公约引用多 | 比较法+规范分析 | 侧重国际条约+外国法 | 注意条约的批准状态和保留条款 |

### 调整方式

- **术语层**：环节5写作引擎的"法学论证方法"参考文件中，根据领域增补术语表。不同领域的高频术语不同（如刑法中"法益""构成要件"频繁出现是正常的），不应被环节7误判为AI腔。
- **引注层**：环节5的"法学引注规范"中，某些领域有特殊引注习惯（如刑法常引用指导性案例编号，国际法需引用条约全称），可按需追加。
- **检测层**：环节7去AI味的检测词条，不同领域可能有不同的高频词分布。使用时应根据领域校准弹性检测阈值，避免将领域惯用表达误判为AI痕迹。
- **文献层**：环节4查资料的检索方向，不同领域侧重不同（民商法偏重学理文献，行政法偏重法规文件，经济法偏重政策文件），应根据领域调整检索策略。NCPSSD检索时注意法条编号单独查、同义词扩展查；OpenAlex检索时注意英文法律术语的准确性。
- **生态层**：环节8法律生态审查的地域适配性检查，不同领域的制度生态差异较大（如刑法关注司法适用统一性，行政法关注执法体制兼容性），应根据领域调整审查重点。
