# 法律生态可落地性审查器

## 定位

本技能是论文生产线的**可选环节8**。在环节7（文风处理）通过后、定稿前，对论文中提出的对策/建议进行法律生态可落地性审查。

**这不是"发表论文"的必经环节，而是"建议能否真正落地"的独立把关。**

### 与模块B的区别

| 维度 | 模块B（环节6的一个评估维度） | 环节8（独立审查环节） |
|------|----------------------------|----------------------|
| 定位 | 快速筛查 | 深度审查 |
| 范围 | 四要素（主体、路径、体制、成本） | 六项全面审查 |
| 输出 | 1-5分评分+说明 | 独立审查报告+逐项通过/不通过判定 |
| 触发 | 论文含建议时自动启用 | 手动选择或模块B评分≤2时触发 |
| 后果 | 低分标注"建议落地风险" | 不通过则回退重写建议 |

### 触发条件

以下任一条件满足时启用：

1. 作者选择"决策参考"预设档位
2. 模块B（实操建议可落地性）评分 ≤ 2
3. 作者手动要求进行法律生态审查
4. 论文的目标读者是领导/业务部门决策者

## 六项审查清单

### 审查1 · 制度兼容性

**核心问题**：建议涉及的法律法规是否现行有效？是否与上位法冲突？

| 检查项 | 判定标准 |
|--------|----------|
| 1.1 建议引用的法律法规是否现行有效？ | 逐条核对。如引用已废止法规，标记"制度兼容性不通过"。 |
| 1.2 建议是否与上位法冲突？ | 如建议与法律/行政法规冲突，是否说明了冲突解决方案？ |
| 1.3 建议是否与同位法协调？ | 如建议涉及多个同位法，是否说明了协调机制？ |
| 1.4 建议是否需要修改现行法？ | 如需要，是否说明了修改路径和可行性？ |
| 1.5 建议是否考虑了立法趋势？ | 如相关法律正在修订，建议是否与修订方向兼容？ |
| 1.6 【实务轨】建议是否与线索卡受困主体所适用的制度框架兼容？ | 如线索卡受困主体为"企业法务"，建议是否与企业现行合规制度框架兼容？ |

**否决项**：如建议与现行上位法冲突且未说明解决方案 → 制度兼容性不通过（自动触发回退）

---

### 审查2 · 主体可行性

**核心问题**：建议涉及的主管部门/执行主体是否真实存在？职责权限是否匹配？

| 检查项 | 判定标准 |
|--------|----------|
| 2.1 建议涉及的主管部门是否真实存在？ | 核对部门设置。如建议"由XX部门负责"但该部门不存在，不通过。 |
| 2.2 主管部门的职责权限是否覆盖建议内容？ | 如建议要求某部门行使超出其法定职权的职能，不通过。 |
| 2.3 多部门协同是否有协调机制？ | 如建议涉及多部门，是否说明了协调机制和牵头部门？ |
| 2.4 执行主体是否有足够的能力？ | 执行主体是否有相应的人员、专业能力、技术条件？ |
| 2.5 建议是否考虑了主体变动风险？ | 如机构改革可能导致主体撤并，建议是否有应对方案？ |

**否决项**：如建议涉及的主管部门不存在或明显超越职权 → 主体可行性不通过

---

### 审查3 · 程序可行性

**核心问题**：建议的操作路径是否符合现行行政/司法程序？

| 检查项 | 判定标准 |
|--------|----------|
| 3.1 建议的操作步骤是否符合现行程序？ | 如建议要求绕开法定程序，不通过。 |
| 3.2 建议是否考虑了程序时限？ | 如建议的操作周期超出法定时限，是否说明了例外安排？ |
| 3.3 建议是否涉及新设程序？ | 如涉及，是否说明了设立依据和合法性基础？ |
| 3.4 建议是否考虑了程序衔接？ | 多个程序之间的衔接是否顺畅？是否存在程序空转？ |
| 3.5 建议是否考虑了当事人的程序权利？ | 如建议涉及当事人权利义务，是否保障了陈述、申辩、救济等程序权利？ |

---

### 审查4 · 资源可行性

**核心问题**：建议的实施成本是否在合理范围？是否有配套资源？

| 检查项 | 判定标准 |
|--------|----------|
| 4.1 建议是否进行了成本评估？ | 如完全没有成本考量，标记"资源可行性不足"。 |
| 4.2 实施成本是否在合理范围？ | 与同类制度实施的常规成本比较。如显著超出，不通过。 |
| 4.3 是否有配套资源保障？ | 人员、经费、技术、场地等配套资源是否有来源？ |
| 4.4 成本分担机制是否明确？ | 谁来承担成本？分担是否合理？ |
| 4.5 是否考虑了长期运营成本？ | 如建议涉及长效机制，是否考虑了持续运营成本？ |

---

### 审查5 · 政策兼容性

**核心问题**：建议是否与当前政策导向一致？是否存在政策障碍？

| 检查项 | 判定标准 |
|--------|----------|
| 5.1 建议是否与当前国家政策导向一致？ | 检查与近期重大政策文件是否协调。如存在冲突，是否说明了理由？ |
| 5.2 建议是否与行业监管政策兼容？ | 如涉及特定行业，是否与行业监管政策协调？ |
| 5.3 建议是否考虑了政策变动风险？ | 政策可能调整，建议是否有适应性？ |
| 5.4 建议是否与改革方向一致？ | 如与当前改革方向相悖，是否充分论证了理由？ |
| 5.5 建议是否考虑了国际政策环境？ | 如涉及涉外事项，是否考虑了国际政策环境？ |

---

### 审查6 · 地域适配性

**核心问题**：建议是否考虑了不同地区的实践差异？

| 检查项 | 判定标准 |
|--------|----------|
| 6.1 建议是否具有普遍适用性？ | 还是仅适用于特定地区？如仅适用特定地区，是否说明了？ |
| 6.2 建议是否考虑了地区发展差异？ | 发达地区和欠发达地区的实施条件不同，建议是否考虑了？ |
| 6.3 建议是否考虑了地方立法差异？ | 如涉及地方事务，是否考虑了各地立法差异？ |
| 6.4 建议是否考虑了地方实践惯例？ | 各地实践惯例不同，建议是否留有弹性？ |
| 6.5 建议是否有地区试点路径？ | 如全面推行有困难，是否建议了试点路径？ |

## 执行流程

```
步骤1：接收终稿
  - 读取环节7通过的终稿
  - 如为实务轨，读取"实务问题线索卡"
  - 提取论文中的所有对策/建议/方案
  - 如论文不包含对策建议，标记"无建议可审"并结束
  - 【实务轨】检查：对策建议是否直接回应了线索卡的痛点？如未回应→标注"线索卡痛点未回应"
  ↓
步骤2：六项逐项审查
  - 按上述六项清单逐项检查
  - 每项给出"通过/不通过/部分通过"判定和具体发现
  ↓
步骤3：交叉检查
  - 六项之间是否有交互影响？
  - 如"制度兼容性不通过"是否导致"程序可行性"也不通过？
  ↓
步骤4：识别关键风险
  - 哪些项不通过？
  - 不通过的根本原因是什么？
  - 是否可以通过修改建议来解决？
  ↓
步骤5：输出审查报告
  - 六项审查结果汇总
  - 关键风险（最多3个）
  - 修改建议（可操作的）
  - 通过/回退判定
```

## 通过/回退判定

### 通过条件（全部满足）

- 六项中至少四项通过
- 制度兼容性必须通过（否决项）
- 主体可行性必须通过（否决项）

### 回退条件（任一触发）

- 制度兼容性不通过 → 回退到环节5（重写建议部分），或回退到环节2（重新梳理思路）
- 主体可行性不通过 → 回退到环节5（重写建议部分）
- 三项及以上不通过 → 回退到环节5（重写建议部分）
- 综合评估"建议无法落地" → 回退到环节2（论证框架需要调整）

### 回退后的操作

回退不意味着放弃论文。回退后作者根据审查报告修改建议部分，常见调整方向：

- **制度冲突**：修改建议使其与现行法兼容，或增加"需修改XX法"的前提说明
- **主体不存在**：改为现存主体，或说明"需设立XX部门"的条件
- **程序不可行**：调整操作路径使其符合现行程序
- **资源不足**：缩减建议规模，或增加分步实施路径
- **政策障碍**：调整建议方向，或增加政策变动的应对预案
- **地域差异**：增加地区适配条款，或改为试点路径

## 输出底线

- **不替作者改建议**。只审查建议的可落地性。
- **每项判定必须附带具体理由**。不能只说"不通过"。
- **制度兼容性核查必须真实核对法规**。不能凭记忆判断"这个法条存不存在"。
- **主体可行性核查必须核对部门设置**。不能凭想象判断"这个部门存不存在"。
- **修改建议必须可操作**——不说"建议需要完善"，说"建议第X项的操作主体应从XX改为XX，因为XX"。
- **审查报告须如实呈现**。不能因为"建议方向正确"就放过可落地性问题。
- **实务轨必须读取并消费线索卡**——检查建议是否回应了线索卡痛点，是否与线索卡受困主体的制度框架兼容。

## 独立使用

也可独立使用本技能，不依赖生产线。当作者有一份包含对策建议的论文/报告，想检查建议能否真正落地时，直接使用本技能进行审查。
