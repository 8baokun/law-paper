# 应用法学论文写作生产线·总入口

## 定位

本技能是论文生产线的**轻量路由器**，不执行具体环节工作。

**做什么**：
- 根据用户当前状态确定从哪个环节进入
- 声明预设档位（学研标准/实务应用/决策参考/自定义）
- 判断是否满足快速通道条件
- 回溯时导航到正确环节
- 检查各环节之间的数据接口是否对齐

**不做什么**：
- 不复制各环节的维度、权重、阈值、否决规则
- 不替代任何环节技能执行具体工作
- 不做评估打分
- 不做内容生成

> 维度名称、权重、通过阈值、否决规则和回退路径以各环节 SKILL.md 为唯一权威源。

## 环节路由表

| 环节 | 技能名 | 输入 | 输出 | 通过条件 | 回退到 |
|------|--------|------|------|----------|--------|

| 环节3 提纲审查 | paper-outline-reviewer | 环节2框架文档+正式提纲 | 提纲审查报告 | 以该技能SKILL.md为准 | 环节2 |
| 环节4 文献检索 | paper-literature-coordinator | 环节3通过的提纲+环节1综述报告 | 标准化文献清单+阅读笔记 | 文献覆盖所有前置论点 | 扩大检索后重新评估 |

| 元认知 | systems-thinking | 任何环节的中间产物 | 诊断报告 | — | — |

## 使用流程

### 步骤1：确定入口

询问用户当前状态，判断从哪个环节进入：

| 用户状态 | 入口环节 | 说明 |
|----------|----------|------|
| "我想写论文但还没选题" | 环节1 | 先做选题检查 |
| "我已经有选题了" | 环节1 | 仍需选题检查验证可行性 |
| "选题已经定了，想理思路" | 环节2 | 需提供选题诊断报告或选题表述 |
| "思路清楚了，想列提纲" | 环节3 | 需提供环节2的论证框架文档 |
| "提纲写好了，要查资料" | 环节4 | 需提供环节3通过的提纲 |
| "资料齐了，开始写" | 环节5 | 需提供环节3提纲+环节4文献清单 |
| "初稿写完了，要检查" | 环节6 | 核验论证强度 |
| "论证没问题，去AI腔" | 环节7 | 文风处理 |
| "终稿好了，查能不能落地" | 环节8 | 生态审查（需选决策参考预设） |
| "写到一半卡住了" | 元认知 | 调用systems-thinking诊断 |

### 步骤2：声明预设

如用户未声明预设，默认使用"学研标准"。提示用户可选择：

| 预设 | 适用场景 | 加载模块 |
|------|----------|----------|
| 学研标准（默认） | 期刊投稿、学位论文 | 无 |
| 实务应用 | 实务部门内刊、行业研讨 | 模块A+模块B |
| 决策参考 | 供领导/业务部门决策参考 | 模块A+模块B+环节8 |
| 自定义 | 用户自行指定 | 自行选择 |

> 预设的详细配置见 `预设配置说明.md`。各环节根据预设自动调整行为，无需手动配置。

### 步骤3：路由到对应环节技能

确定入口环节和预设后，调用对应环节的技能。调用时需传递：
- 预设档位
- 上游环节的输出文档（如有）
- 实务问题线索卡（实务轨，如有）

### 步骤4：通过/回退判断

环节执行完毕后，根据该环节SKILL.md中的通过条件判断：
- **通过** → 进入下一环节
- **不通过** → 按回溯协议退回对应环节
- **快速通道** → 检查是否满足快速通道条件

### 步骤5：快速通道判断

```
上游环节评分 ≥ 4.5/5.0 → 下游环节启用简化模式
但环节6和环节7不可跳过
```

如环节1综合评分≥4.5 → 环节2可启用简化模式（跳过步骤4深挖）。
如环节3+环节4+环节5综合评分均≥4.5 → 环节6可启用简化模式（仅评估两个核心维度）。

### 步骤6：终稿总检

环节7（或环节8，如启用）通过后，建议执行终稿总检：
→ 调用 `paper-final-checklist` 技能，做最终复核。

## 数据接口对齐检查

各环节之间的数据传递须满足接口要求：

| 上游→下游 | 接口文档 | 对齐检查点 |
|-----------|----------|------------|
| 环节1→环节2 | 选题诊断报告 | 核心命题是否可凝练 |
| 环节2→环节3 | 标准化论证框架文档 | 论证线索是否与提纲一致 |
| 环节3→环节4 | 提纲审查报告 | 提纲是否通过 |
| 环节4→环节5 | 标准化文献清单+阅读笔记 | 文献是否覆盖所有前置论点 |
| 环节5→环节6 | 论文初稿 | 初稿是否完整 |
| 环节6→环节7 | 论文学证强度评估报告 | 综合评分是否≥3.0 |
| 环节7→环节8 | 去AI腔终稿 | 文风检测是否通过 |

如数据接口不对齐，标记"接口断裂"，要求补全后再进入下一环节。

## 实务问题线索卡传递链（实务轨）

```
环节1：产出线索卡 → 状态：活跃
  ↓
环节2：读取线索卡，章节规划对应痛点 → 状态：活跃
  ↓
环节3：读取线索卡，检查提纲有对应章节 → 状态：活跃
  ↓
环节4：读取线索卡，定向检索实务文献 → 状态：活跃
  ↓
环节5：读取线索卡，对策建议回应痛点 → 状态：已回应
  ↓
环节6：模块B第7项检查通过 → 状态：已关闭
  ↓（如未通过）
任何环节未回应 → 保持活跃，触发回溯
```

## 回溯协议速查

```
环节1 不通过        → 修改选题后重新提交
环节2 命题无法凝练   → 环节1
环节3 提纲不对齐     → 环节2
环节4 文献覆盖不足   → 扩大检索后重新评估
环节5 发现文献不足   → 环节4
环节5 发现框架问题   → 环节2
环节6 综合评分<3.0  → 环节5
环节6 增量缺失      → 环节2
环节6 法源错误      → 环节4
环节6 引注严重缺陷   → 环节5
环节6 文献幻觉      → 环节4或环节5
环节6 模块B闭环未过  → 环节5（重写对策建议）
环节7 发现实质问题   → 环节5
环节8 不通过        → 环节5或环节2
```

> 各环节回退的详细条件以该环节SKILL.md为准。

## 单环节使用

用户也可以跳过总入口，直接使用任意环节技能：

- 只想检查选题 → `paper-topic-validator`
- 只想梳理思路 → `paper-idea-architect`
- 只想审查提纲 → `paper-outline-reviewer`
- 只想系统检索文献 → `paper-literature-coordinator`
- 只想撰写论文 → `paper-writing-engine`
- 只想核验论证强度 → `paper-argument-evaluator`
- 只想去AI腔 → `de-ai-polish`
- 想审视方案结构 → `systems-thinking`
- 想审查建议可落地性 → `legal-ecology-reviewer`
- 终稿做最终复核 → `paper-final-checklist`

## 与其他技能的协作

本技能是路由器，不执行具体工作。所有评估、生成、检测工作由各环节技能完成。

| 协作方向 | 技能 | 关系 |
|----------|------|------|
| 路由到环节1 | paper-topic-validator | 总入口调用 |
| 路由到环节2 | paper-idea-architect | 总入口调用 |
| 路由到环节3 | paper-outline-reviewer | 总入口调用 |
| 路由到环节4 | paper-literature-coordinator | 总入口调用 |
| 路由到环节5 | paper-writing-engine | 总入口调用 |
| 路由到环节6 | paper-argument-evaluator | 总入口调用 |
| 路由到环节7 | de-ai-polish | 总入口调用 |
| 路由到环节8 | legal-ecology-reviewer | 总入口调用（可选） |
| 元认知介入 | systems-thinking | 任意环节可调用 |
| 终稿复核 | paper-final-checklist | 环节7/8后调用 |
