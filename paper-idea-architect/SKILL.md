# 应用法学论文思路梳理器

## 概述

本技能是应用法学论文生产线的环节2。在环节1（选题检查）通过后、环节3（提纲审查）之前，帮助作者完成从选题到提纲之间的"思路打通"。

输出是**标准化论证框架文档**——不是论文正文，也不是提纲，而是论证骨架。

> **实务轨提示**：如使用"实务应用"或"决策参考"预设，思路梳理时需额外关注实务问题的论证线索——确保论证框架中有专门章节回应环节1模块A识别的实务痛点，并在章节规划中预留"问题对策"或"案例评析"的空间。推荐结构模式参见环节5论文结构模式五、六。
>
> **线索卡强制消费（实务轨）**：如上游环节1产出了"实务问题线索卡"，本环节必须：
> 1. 读取线索卡中的痛点描述、受困主体、规范缺口类型
> 2. 在章节规划中确保有一个章节标题直接对应线索卡的"痛点描述"
> 3. 在标准化论证框架文档的"章节规划"部分标注该章节与线索卡的对应关系
> 4. 如未对应 → 标记"实务线索断裂"，要求补全后再进入环节3

## 核心能力

### 能力一：思路梳理（主模式）

#### 定位

| 项目 | 内容 |
|------|------|
| 环节 | 论文生产线环节2 |
| 输入 | 环节1的选题诊断报告（通过的选题） |
| 输出 | 标准化论证框架文档 |
| 下游 | 环节3（提纲审查） |

#### 执行流程（9步）

```
步骤1：接收选题检查结果
  - 读取环节1的选题诊断报告
  - 如为实务轨，读取选题诊断报告末尾的"实务问题线索卡"
  - 确认选题已通过（五维综合评分≥3.5）
  ↓
步骤2：核心命题凝练
  - 将选题表述凝练为一句话的核心命题
  - 核心命题=论文要证明的判断句
  - 示例："《合规管理办法》第26条规定的业法财融合机制具有规范层面的可操作性"
  ↓
步骤2.5：方法选择路由
  - 根据核心命题的特征，推荐论文结构模式和主要论证方法
  - 这一步的产出会写入标准化论证框架文档的"方法选择"部分
  - 供环节5（论文写作）参考，环节3（提纲审查）检查一致性
  ↓
步骤3：论证线索梳理
  - 从核心命题出发，倒推论证需要的支撑
  - 识别：核心主张→前置论点→依据类型→反驳回应
  - 不写正文，只搭论证骨架
  ↓
步骤4：前置论点检验
  - 每个前置论点是否需要独立论证？
  - 如需要，标记为"需论证前提"
  - 如不需要（已有共识或已有文献充分论证），标记为"已成立前提"
  ↓
步骤5：依据类型标注
  - 为每个论点标注所需的依据类型：
    [L]法律规范依据——需要援引具体法条
    [F]事实/案例依据——需要案例或数据
    [S]学理依据——需要引用学说
    [P]政策依据——需要引用政策文件
    [C]比较法依据——需要外国法参照
  ↓
步骤6：反驳预判
  - 对核心命题预判可能的反对意见
  - 为每个反对意见准备回应方向
  - 这构成论证回路闭合的"回应反驳"环节
  ↓
步骤7：章节规划
  - 基于论证线索，初步规划一级标题框架
  - 不是正式提纲（那是环节3的事），只是论证线索的章节映射
  - 【实务轨】检查：章节规划中是否有标题直接对应线索卡的"痛点描述"？如无→标记"实务线索断裂"，要求补全
  ↓
步骤8：输出标准化论证框架文档
  - 按标准格式输出
  - 这是环节3（提纲审查）的输入
```

#### 步骤2.5详解：方法选择路由

在核心命题凝练后、论证线索梳理前，根据命题特征选择最合适的论文结构模式和论证方法。

**结构模式选择矩阵**：

| 命题特征 | 推荐模式 | 适用轨道 |
|----------|----------|----------|
| 分析某一制度的规范构造和实施效果 | 模式一：制度分析型 | 学研轨/实务轨 |
| 解释某一条文/概念的含义，解决适用争议 | 模式二：规范解释型 | 学研轨/实务轨 |
| 基于案例/数据的实证分析 | 模式三：实证研究型 | 学研轨/实务轨 |
| 比较中外制度差异，提炼本土化路径 | 模式四：比较法研究型 | 学研轨/实务轨 |
| 以实务问题为起点，分析规范困境，给可操作对策 | 模式五：问题对策型 | 实务轨推荐 |
| 从个案/类案切入，提炼规则适用路径 | 模式六：案例评析型 | 实务轨推荐 |

**选择规则**：

1. 如核心命题指向"某制度怎么样/怎么完善" → 模式一
2. 如核心命题指向"某条文/概念应如何理解" → 模式二
3. 如核心命题指向"某类案件的裁判规律/数据特征" → 模式三
4. 如核心命题指向"中外制度比较/借鉴" → 模式四
5. 如核心命题指向"某实务问题怎么解决" → 模式五（实务轨首选）
6. 如核心命题指向"某案/某类案应如何适用法律" → 模式六（实务轨首选）
7. 如命题特征跨多个模式 → 选主要模式，标注次要模式作为辅助
8. 实务轨用户如未明确指定 → 优先推荐模式五或六
9. 学研轨用户如未明确指定 → 根据命题特征从模式一至四中选择

**论证方法推荐**（与结构模式配合）：

| 结构模式 | 主要论证方法 | 辅助论证方法 |
|----------|-------------|-------------|
| 制度分析型 | 规范分析、体系解释 | 案例分析、比较法 |
| 规范解释型 | 文义解释、体系解释、目的解释 | 历史解释、社会学解释 |
| 实证研究型 | 统计分析、归纳推理 | 规范分析、类型化分析 |
| 比较法研究型 | 比较分析、功能主义方法 | 历史分析、规范分析 |
| 问题对策型 | 规范分析、成因分析 | 案例分析、类型化分析 |
| 案例评析型 | 案例分析、规则提炼 | 规范分析、体系解释 |

> 结构模式和论证方法的详细说明见 `paper-writing-engine/references/论文结构模式.md` 和 `paper-writing-engine/references/法学论证方法.md`。

#### 标准化论证框架文档格式

```markdown
# 标准化论证框架

## 1. 核心命题
[一句话表述的核心命题]

## 1.5 方法选择
- **推荐结构模式**：[模式一至六中的哪一个，及选择理由]
- **辅助模式**：[如有，标注]
- **主要论证方法**：[规范分析/文义解释/统计分析/比较分析/案例分析等]
- **辅助论证方法**：[如有，标注]

## 2. 论证线索

### 2.1 核心主张
[核心主张的完整表述]

### 2.2 前置论点

| 编号 | 前置论点 | 是否需独立论证 | 依据类型 | 依据来源 |
|------|----------|----------------|----------|----------|
| P1 | [论点1] | [需论证/已成立] | [L/F/S/P/C] | [法条/案例/学说/政策/外国法] |
| P2 | [论点2] | ... | ... | ... |

### 2.3 论证结构图

[核心主张]
  ├── [前置论点P1] ← [依据类型L] ← [具体法条]
  ├── [前置论点P2] ← [依据类型F] ← [具体案例]
  ├── [前置论点P3] ← [依据类型S] ← [具体学说]
  └── [反驳回应R1] ← [对反对意见的回应]

### 2.4 反驳预判

| 编号 | 可能的反对意见 | 回应方向 | 依据类型 |
|------|----------------|----------|----------|
| R1 | [反对意见1] | [回应方向] | [L/F/S] |
| R2 | [反对意见2] | [回应方向] | [L/F/S] |

## 3. 章节规划（初步）

| 章节 | 对应论证线索 | 预估篇幅占比 |
|------|--------------|--------------|
| 一、问题提出 | 核心命题+问题意识 | 10-15% |
| 二、[规范分析章节] | P1+P2 | 25-35% |
| 三、[案例分析章节] | P3 | 15-25% |
| 四、[制度建议章节] | 核心主张的建构层面 | 15-20% |
| 五、结论 | 核心命题的重申和推进 | 5-10% |

## 4. 待解决问题清单

| 编号 | 待解决问题 | 影响哪个论点 | 优先级 |
|------|------------|--------------|--------|
| Q1 | [需进一步研究的问题] | [P1/P2/...] | [🔴/🟡/🟢] |

## 5. 数据接口声明

- 本文档为环节3（提纲审查）的输入
- 环节3将基于本文档的论证线索审查正式提纲
- 如提纲与本文档的论证线索不一致，环节3将标记"数据接口不对齐"
```

#### 思路梳理模式的输出底线

- **不写论文正文**。只搭论证骨架。
- **核心命题必须是一句话的判断句**，不能是话题。
- **方法选择必须标注推荐模式及选择理由**，不能空缺。
- **每个前置论点必须标注是否需要独立论证**，不能含糊。
- **依据类型必须具体标注**，不能笼统说"有依据"。
- **反驳预判至少列出2个可能的反对意见**。
- **章节规划是初步的**，不替代正式提纲。
- **待解决问题清单必须如实列出尚未解决的问题**。
- **实务轨必须读取并消费线索卡**——章节规划中必须有直接对应线索卡"痛点描述"的章节，否则标记"实务线索断裂"。

### 能力二：学术写作基础

思路梳理中引用的法条、案例、学说必须是真实的，遵循以下学术规范：

#### 引用规范

- **法条引用**：标注法律名称、条款号、施行日期。如引用已废止法条，必须说明理由。
- **案例引用**：标注裁判文书号、裁判法院、裁判日期。
- **学说引用**：标注作者、著作/论文标题、出处、页码/页范围。
- **政策文件引用**：标注文件名称、文号、发布机关、发布日期。
- **比较法引用**：标注法域、法源名称、译文出处。

#### 学术诚信

- **绝不捏造数据、证据或引用**。
- 所有引用的法条、案例、学说必须是真实可查证的。
- 如不确定某条信息的准确性，标注"[待验证]"并说明原因。

#### 输出格式

- 使用Markdown格式输出。
- 标准化论证框架文档不需要`<ama-doc>`标签（该标签仅用于论文正文输出）。

## 回溯协议

- 如核心命题无法凝练为一句话判断句 → 回退到环节1（选题检查），选题可能不够明确
- 如前置论点全部需要独立论证且相互依赖 → 选题可能过于复杂，建议拆分或聚焦
- 如反驳预判发现致命反对意见且无法回应 → 核心命题可能不成立，需重新考虑

## 快速通道

- 如环节1（选题检查）综合评分 ≥ 4.5 → 思路梳理可启用简化模式：跳过步骤4（前置论点检验）的逐项深挖，直接标注后进入步骤5
- 但步骤2（核心命题凝练）、步骤2.5（方法选择）和步骤8（输出文档）不可跳过

## 独立使用

也可独立使用本技能，不依赖生产线。当作者有一个选题但还不知道怎么论证时，使用思路梳理帮助打通思路。
