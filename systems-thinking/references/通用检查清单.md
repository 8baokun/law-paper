# 通用检查清单（详细版）

> 本文件是 SKILL.md 六维框架的展开。仅在需要逐项详细检查时读取，不需要整篇加载。

---

## 维度1 · 整体性分析

### 检查问题

| 编号 | 检查问题 | 判定方式 |
|------|----------|----------|
| 1.1 | 各组成部分是否服务于同一个核心目标？ | 列出每个部分的目标，与核心目标对照。如有部分目标与核心目标无关，标记为游离。 |
| 1.2 | 是否存在"为了存在而存在"的部分？ | 问：如果移除这个部分，整体是否仍然成立？如成立且无损失，该部分为冗余。 |
| 1.3 | 整体效果是否大于部分之和？ | 识别部分之间的协同效应。如无协同，整体只是部分的简单堆砌。 |
| 1.4 | 是否有缺失的部分？ | 对照核心目标，推导完成目标需要哪些部分，逐一检查是否齐全。 |
| 1.5 | 部分之间的比例是否合理？ | 某个部分是否过度膨胀或过度压缩？比例失调会导致整体失衡。 |

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 各部分高度协同，整体远大于部分之和 |
| 4 | 各部分基本协同，无游离部分 |
| 3 | 存在轻微的游离或冗余，但不影响整体功能 |
| 2 | 存在明显的游离部分或缺失部分 |
| 1 | 各部分各自为政，缺乏整体性 |

## 维度2 · 耦合关系

### 检查问题

| 编号 | 检查问题 | 判定方式 |
|------|----------|----------|
| 2.1 | 哪些环节之间存在强依赖？ | 画出依赖图。A的输出是B的必要输入=强依赖。 |
| 2.2 | 哪些环节之间存在弱依赖？ | A的输出影响B的质量但不阻断=弱依赖。 |
| 2.3 | 是否存在双向耦合？ | A依赖B且B依赖A。如有，检查是否导致死锁或需要打破循环。 |
| 2.4 | 数据接口是否对齐？ | 强依赖环节之间，输出格式是否与输入要求匹配？ |
| 2.5 | 耦合强度是否合理？ | 过度耦合（改一处牵动全局）vs 过度松散（各环节无法协同）。 |

### 依赖图模板

```
[A] --强依赖--> [B] --弱依赖--> [C]
 ↑                              |
 └----------反馈(负)------------+
```

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 依赖关系清晰，接口对齐，无死锁风险 |
| 4 | 依赖关系基本清晰，个别接口需微调 |
| 3 | 存在接口不对齐或耦合过紧，但不阻断流程 |
| 2 | 存在死锁风险或严重接口不匹配 |
| 1 | 依赖关系混乱，无法追踪数据流向 |

## 维度3 · 涌现性

### 检查问题

| 编号 | 检查问题 | 判定方式 |
|------|----------|----------|
| 3.1 | 多环节同时运行是否产生信息过载？ | 估算信息流量，判断下游处理能力是否足够。 |
| 3.2 | 是否存在负面涌现（1+1<2）？ | 两个环节的功能重叠导致冲突或冗余。 |
| 3.3 | 是否存在正面涌现（1+1>2）？ | 两个环节组合产生新能力。是否已利用？ |
| 3.4 | 组合后的整体行为是否可预测？ | 是否存在不可控的连锁反应？ |
| 3.5 | 并行执行时的竞态条件？ | 多环节同时访问同一资源时是否冲突？ |

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 涌现效应已被识别和利用，无负面涌现 |
| 4 | 存在轻微负面涌现但已有缓解措施 |
| 3 | 存在未利用的正面涌现或未缓解的轻微负面涌现 |
| 2 | 存在显著的负面涌现影响整体功能 |
| 1 | 涌现行为不可控，整体行为不可预测 |

## 维度4 · 反馈回路

### 检查问题

| 编号 | 检查问题 | 判定方式 |
|------|----------|----------|
| 4.1 | 识别所有负反馈循环。 | 画出"发现问题→修正→再检查"的路径。 |
| 4.2 | 负反馈循环是否闭合？ | 修正后是否有路径回到检查环节？如无，为开环。 |
| 4.3 | 识别所有正反馈循环。 | 画出"做得好→增强→更好"的路径。 |
| 4.4 | 正反馈是否有失控风险？ | 正反馈循环是否有阻尼机制？ |
| 4.5 | 反馈延迟有多大？ | 从发现问题到修正生效的时间差。延迟过大导致过冲。 |
| 4.6 | 是否存在"开环"（发现问题但无修正路径）？ | 检查每个"发现问题"的环节，是否有对应的修正路径。 |

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 所有反馈回路闭合，延迟合理，无开环 |
| 4 | 个别回路延迟较大，但基本闭合 |
| 3 | 存在开环或延迟过大，但不影响核心流程 |
| 2 | 关键反馈回路未闭合，问题无法回传 |
| 1 | 无反馈机制，流程为纯开环 |

## 维度5 · 盲区扫描

### 检查方法

#### 方法1：隐含假设枚举

```
列出方案中所有"默认成立但未显式声明"的前提：
1. [假设1]：[是否成立？如不成立，后果是什么？]
2. [假设2]：[是否成立？如不成立，后果是什么？]
...
```

#### 方法2：反向思考

```
如果核心方案完全错误，最可能的原因是什么？
- 不是"方案哪里有问题"，而是"什么情况下整个方案会崩溃"
- 列出top 3崩溃场景
```

#### 方法3：利益相关方扫描

```
谁会受到这个方案的影响？
- 直接使用者：[已考虑？]
- 间接影响者：[已考虑？]
- 被排除者：[是否有意排除？为什么？]
```

#### 方法4：异常路径检查

```
方案是否只考虑了正常路径？
- 输入不完整时怎么办？
- 中间环节失败时怎么办？
- 上游输出质量极差时怎么办？
- 用户跳过某环节时怎么办？
```

#### 方法5：参照 references/盲区扫描清单.md

获取系统化的盲区枚举辅助。

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 盲区扫描穷尽，所有隐含假设已显式化 |
| 4 | 主要盲区已识别，个别隐含假设未显式化 |
| 3 | 存在未识别的盲区，但不影响方案核心 |
| 2 | 存在重大盲区，可能导致方案在特定条件下失败 |
| 1 | 盲区扫描不充分，方案可能在未知条件下崩溃 |

## 维度6 · 边界条件

### 检查问题

| 编号 | 检查问题 | 判定方式 |
|------|----------|----------|
| 6.1 | 方案在什么条件下有效？ | 列出所有必要条件。 |
| 6.2 | 方案在什么条件下失效？ | 列出所有失效条件。不是"可能失效"，而是"一定失效"。 |
| 6.3 | 边界是否已显式声明？ | 检查方案文档中是否有边界声明段落。 |
| 6.4 | 方案是否可推广？ | 推广到其他场景时，哪些条件需要调整？ |
| 6.5 | 复杂度是否与场景匹配？ | 过度设计（简单场景用复杂方案）vs 设计不足（复杂场景用简单方案）。 |

### 边界声明模板

```
## 边界声明

### 适用范围
[列举方案适用的场景、领域、条件]

### 不适用
[列举方案不适用的场景]

### 前置条件
[列举方案运行前必须满足的条件]

### 失效条件
[列举方案一定失效的条件]

### 推广限制
[推广到其他场景时需要调整的条件]
```

### 评分

| 分值 | 含义 |
|------|------|
| 5 | 边界条件完全显式化，适用范围和失效条件清晰 |
| 4 | 主要边界已声明，个别边界隐含 |
| 3 | 边界部分声明，存在未覆盖的失效条件 |
| 2 | 边界 largely 未声明，方案可能在未预期的条件下失效 |
| 1 | 无边界声明，方案适用范围不清 |
