# 系统思维

## 定位

本技能是元认知工具，不是内容生产工具。它的作用是审视——看结构、看关系、看遗漏、看边界。

输出永远是诊断报告，不是论文、不是方案、不是写作内容。

## 六维框架

### 维度1 · 整体性分析

**核心问题**：各部分是否构成连贯的整体？有无游离的部分？

通用检查清单：
- 各组成部分是否服务于同一个核心目标？
- 是否存在"为了存在而存在"的部分（不服务于核心目标）？
- 移除任何一个部分后，整体是否仍然成立？（如成立，该部分可能是冗余的）
- 整体效果是否大于部分之和？（如不大于，说明缺乏协同）

### 维度2 · 耦合关系

**核心问题**：各环节之间的依赖方向和强度是什么？

通用检查清单：
- 哪些环节之间存在强依赖（一个的输出是另一个的必要输入）？
- 哪些环节之间存在弱依赖（一个的输出影响另一个的质量，但不阻断）？
- 是否存在双向耦合（A依赖B且B依赖A）？如有，是否会导致死锁？
- 数据格式/接口是否对齐？强依赖环节之间是否有标准化接口？

### 维度3 · 涌现性

**核心问题**：多个部分组合后是否产生预期之外的效果？

通用检查清单：
- 多个环节同时运行时，是否会产生信息过载或冲突？
- 是否存在"1+1<2"的负面涌现（组合后互相干扰）？
- 是否存在"1+1>2"的正面涌现（组合后产生新能力）？是否已充分利用？
- 组合后的整体行为是否可预测？有无不可控的涌现行为？

### 维度4 · 反馈回路

**核心问题**：存在哪些正反馈和负反馈循环？是否闭合？

通用检查清单：
- 识别所有负反馈循环（发现问题→修正→再检查）。循环是否闭合（修正后能回到检查环节）？
- 识别所有正反馈循环（做得好→增强→做得更好）。是否有失控风险？
- 反馈的延迟有多大？延迟是否导致过冲或振荡？
- 是否存在"开环"（发现问题但无路径回到修正环节）？

### 维度5 · 盲区扫描

**核心问题**：主动枚举没想到的——哪些假设是隐含的？

通用检查清单：
- 列出所有隐含假设。每个假设是否成立？
- 从反面思考：如果核心方案完全错误，最可能的原因是什么？
- 是否存在"所有人都知道但没人说出来"的问题？
- 方案是否只考虑了正常路径？异常路径（失败、超时、部分可用）如何处理？
- 是否有被忽略的利益相关方或受影响方？

### 维度6 · 边界条件

**核心问题**：方案的适用范围和失效条件是什么？

通用检查清单：
- 方案在什么条件下有效？
- 方案在什么条件下失效？（不是"可能失效"，而是"一定失效"）
- 边界是否已明确声明？还是隐含的？
- 方案是否可推广？推广时哪些条件需要调整？
- 方案的复杂度是否与使用场景匹配？（过度设计 vs 设计不足）

## 执行流程

```
步骤1：确定分析对象（方案/流程/文档/架构）
  ↓
步骤2：选择应用模式
  - 通用模式：使用上述通用检查清单
  - 法学应用模式：读取 references/法学应用模式.md，使用特化检查问题
  ↓
步骤3：逐维度分析（按需读取 references/通用检查清单.md 获取详细版）
  ↓
步骤4：交叉分析
  - 六维之间是否有交互影响？（如耦合关系导致新的涌现性）
  - 是否存在跨维度的盲区？
  ↓
步骤5：输出诊断报告（按 references/诊断报告模板.md 格式）
```

## 输出底线

- 只做诊断，不做替代。指出问题，不替别人重写方案。
- 每个发现必须可操作——不说"有问题"，说"什么环节的什么问题，影响什么，建议怎么改"。
- 盲区扫描必须主动穷举，不能只列出"顺便想到的"。
- 边界条件必须显式声明，不能隐含。
- 如选择法学应用模式，使用系统思维的语言（耦合、涌现、反馈），不使用系统法学的术语（自创生、二值代码、结构耦合）。
