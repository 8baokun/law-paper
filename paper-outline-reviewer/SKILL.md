# 提纲审查器（Paper Outline Reviewer）

## 定位

本技能是论文生产线的第三个环节。在作者完成思路梳理并输出标准化论证框架文档后，对提纲进行结构化审查。

输出永远是提纲审查报告，不是提纲本身。本技能不替作者写提纲，只审查已写提纲的结构合理性。

> **实务轨提示**：如使用"实务应用"或"决策参考"预设，提纲审查时需额外关注——提纲中是否有专门的"问题对策"或"案例评析"章节？如选题为实务轨且提纲未包含实操建议章节，标记为"结构缺陷：缺少实操建议章节"。推荐结构模式参见环节5论文结构模式五、六。
>
> **线索卡强制消费（实务轨）**：如上游环节2传入了"实务问题线索卡"，本环节必须：
> 1. 读取线索卡中的痛点描述
> 2. 在八项检查中额外检查：提纲中是否有专门章节回应线索卡的痛点？
> 3. 如无对应章节 → 在检查6（问题回应闭环）中标注"未回应实务线索卡痛点"，检查6评分扣分
> 4. 如提纲有对应章节但与线索卡受困主体不匹配 → 标注"回应主体偏移"

## 与上下游的关系

- **上游**：环节2（思路梳理）输出的"标准化论证框架文档"是本环节的输入
- **下游**：环节4（查资料）依赖本环节通过的提纲
- **回溯协议**：本环节不通过→回退到环节2（思路梳理），不是回退到环节1

## 八项检查清单

### 检查1 · 逻辑结构完整性

**核心问题**：提纲是否具备论文的基本结构要素？

| 检查项 | 判定标准 |
|--------|----------|
| 1.1 是否有引言/导论部分？ | 引言应包含问题提出、文献回顾、研究方法和论文结构。 |
| 1.2 是否有明确的论证主体？ | 主体部分应分为若干章节，每章有明确的论证目标。 |
| 1.3 是否有结论部分？ | 结论应回应引言提出的问题，总结核心发现。 |
| 1.4 结构是否呈"提出问题→分析问题→解决问题"的逻辑？ | 应用法学论文的基本逻辑链条。可以有变体，但逻辑链必须完整。 |
| 1.5 是否有过渡章节或过渡段落？ | 章节之间是否有逻辑衔接，而非简单堆砌。 |

**评分**：1-5分（5=结构完整且逻辑连贯，1=结构残缺）

---

### 检查2 · 论证层次清晰度

**核心问题**：提纲的论证层次是否清晰？是否有一级、二级、三级标题的合理分层？

| 检查项 | 判定标准 |
|--------|----------|
| 2.1 一级标题是否对应核心论证步骤？ | 每个一级标题应是一个独立的论证步骤。 |
| 2.1b 一级标题是否不可替代？ | 删除任意一章后，后续论证是否断裂？如断裂可修复（该章内容可并入他章），说明该章可合并。答不出"删除后哪个判断无法成立"的章节应合并或删除。 |
| 2.2 二级标题是否是一级标题的逻辑展开？ | 二级标题应是一级标题的子论证，不是并列话题。 |
| 2.3 三级标题（如有）是否过度碎片化？ | 三级标题过多说明论证碎片化，应合并到二级。 |
| 2.4 标题之间的逻辑关系是否可辨识？ | 看标题就能理解论证的推进逻辑。如看标题仍不知道论证如何推进，层次不清。 |
| 2.5 是否存在"标题即结论"的问题？ | 标题应是论证方向的标注，不是结论的提前宣告。"信义义务的扩张是必然趋势"是结论式标题，"信义义务的扩张趋势"是方向式标题。 |

**评分**：1-5分

---

### 检查3 · 规范分析充分性

**核心问题**：提纲是否为规范分析留有充分空间？

| 检查项 | 判定标准 |
|--------|----------|
| 3.1 是否有专门的规范分析章节？ | 应用法学论文必须有规范分析。检查提纲中是否有分析法律条文的章节。 |
| 3.2 规范分析是否涉及构成要件？ | 检查提纲是否将规范拆解为构成要件并逐一分析。 |
| 3.3 规范分析是否涉及解释争议？ | 检查提纲是否讨论了条文的解释争议。 |
| 3.4 是否有规范适用分析？ | 检查提纲是否分析了规范在具体案件中的适用。 |
| 3.5 规范分析与理论分析的比例是否合理？ | 应用法学论文应以规范分析为主，理论分析为辅。如理论分析占比过大，规范分析不足。 |

**评分**：1-5分

---

### 检查4 · 案例支撑度

**核心问题**：提纲是否有足够的案例支撑论证？

| 检查项 | 判定标准 |
|--------|----------|
| 4.1 是否有案例分析章节？ | 检查提纲中是否有分析具体案例的部分。 |
| 4.2 案例选择是否有代表性？ | 案例应具有典型性，能说明论证的核心问题。 |
| 4.3 案例与规范分析的对应关系是否明确？ | 案例应用来检验规范分析的结论，不是孤立展示。 |
| 4.4 是否考虑了反面案例？ | 仅选择支持论点的案例是"选择性偏差"。应考虑反面案例并作出回应。 |
| 4.5 案例的数量是否足够？ | 一般至少需要3-5个典型案例。仅1个案例支撑力不足。 |

**评分**：1-5分

---

### 检查5 · 文献覆盖面

**核心问题**：提纲是否覆盖了核心文献？

| 检查项 | 判定标准 |
|--------|----------|
| 5.1 是否有文献综述章节？ | 文献综述可独立成章，也可融入引言。但必须有。 |
| 5.2 文献综述是否区分了"已有研究"和"本文增量"？ | 文献综述不只是列举已有研究，还要指出现有研究的缺口。 |
| 5.3 是否覆盖了核心文献？ | 核心文献=与选题直接相关的最重要文献。未覆盖核心文献是重大缺陷。 |
| 5.4 是否有比较法文献？ | 应用法学论文如涉及比较法，需覆盖相关外文文献。 |
| 5.5 文献覆盖的时间范围是否合理？ | 应覆盖最新文献（近5年）和经典文献（奠基性文献）。 |

**评分**：1-5分

---

### 检查6 · 问题回应闭环

**核心问题**：提纲的结论是否回应了引言提出的问题？

| 检查项 | 判定标准 |
|--------|----------|
| 6.1 引言提出的问题是否在结论中得到回答？ | 检查引言的问题和结论的回答是否对应。不对应=开环论证。 |
| 6.2 每个一级标题是否服务于回答核心问题？ | 如有一级标题与核心问题无关，标记为游离部分。 |
| 6.3 是否预见了反对意见并作出回应？ | 检查提纲中是否有"可能的反对意见"部分。 |
| 6.4 论证是否有"提出主张→提供依据→回应反驳→强化主张"的完整回路？ | 缺少"回应反驳"环节=论证回路不闭合。 |
| 6.5 结论是否超出了论证所能支撑的范围？ | 结论应与论证范围匹配。如论证只覆盖A场景，结论不应推广到所有场景。 |
| 6.6 【实务轨】提纲中是否有专门章节回应线索卡的痛点？ | 如有线索卡，提纲中必须有章节直接对应线索卡的"痛点描述"。无对应章节=开环论证。 |

**评分**：1-5分

---

### 检查7 · 篇幅分配合理性

**核心问题**：提纲各部分的篇幅分配是否合理？

| 检查项 | 判定标准 |
|--------|----------|
| 7.1 文献综述占比是否合理？ | 一般10-15%。超过25%说明文献综述过长，挤占了核心论证空间。 |
| 7.2 核心论证占比是否充分？ | 核心论证应占全文50%以上。如核心论证占比低于40%，说明论证不充分。 |
| 7.3 案例分析占比是否合理？ | 一般15-25%。视论文类型而定。 |
| 7.4 是否有部分过度膨胀？ | 某一部分超过全文30%说明该部分过度膨胀。 |
| 7.5 引言和结论的占比是否合理？ | 引言一般10-15%，结论一般5-10%。 |

**评分**：1-5分

---

### 检查8 · 创新点呈现度

**核心问题**：提纲是否清晰地呈现了论文的创新点？

| 检查项 | 判定标准 |
|--------|----------|
| 8.1 创新点是否在引言中预告？ | 读者应在引言中就能知道本文的创新在哪里。 |
| 8.2 创新点是否有对应的论证章节？ | 创新点不能只停留在引言的预告，必须有专门的论证支撑。 |
| 8.3 创新点是否在结论中总结？ | 结论应明确总结"本文在XX方面推进了XX"。 |
| 8.4 创新点的表述是否具体？ | "本文有理论创新"是不具体的。"本文提出了XX要件的新解释"是具体的。 |
| 8.5 创新点是否与已有研究区分？ | 提纲应明确"已有研究认为A，本文认为B"。 |

**评分**：1-5分

## 执行流程

```
步骤1：接收提纲
  - 作者提供完整的论文提纲（含一级、二级标题）
  - 附带环节2输出的"标准化论证框架文档"
  - 如为实务轨，读取"实务问题线索卡"
  ↓
步骤2：八项逐项检查
  - 按上述八项清单逐项检查
  - 每项给出评分（1-5分）和具体发现
  ↓
步骤3：结构问题标注
  - 在提纲上标注问题位置
  - 标注类型：缺失、冗余、错位、比例失调、逻辑断裂
  ↓
步骤4：交叉检查
  - 八项之间是否有交互影响？
  - 如"规范分析不足"是否导致"案例支撑度"也低？
  ↓
步骤5：输出审查报告
  - 八项评分汇总
  - 结构问题清单
  - 修改建议
  - 通过/回退判定
```

## 通过/回退判定

### 通过条件（全部满足）

- 八项综合评分 ≥ 3.5/5.0
- 检查1（逻辑结构）≥ 3分
- 检查6（问题回应闭环）≥ 3分
- 无任何检查项为1分

### 回退条件（任一触发）

- 八项综合评分 < 3.5/5.0
- 检查1（逻辑结构）< 3分
- 检查6（问题回应闭环）< 3分
- 任意检查项为1分

### 回退后的操作

回退到环节2（思路梳理）。常见需要重新梳理的情况：
- 逻辑结构不完整→论证框架需要重新设计
- 问题回应闭环不闭合→核心论证线索需要重新梳理
- 规范分析不足→需要在论证框架中增加规范分析维度
- 创新点不明确→需要重新明确论文的核心贡献

## 快速通道

如果八项综合评分 ≥ 4.5/5.0，且无任何项低于4分，提纲质量优秀，可直接进入环节4（查资料），后续环节可启用简化模式。

## 数据接口对齐

本环节的输入是环节2输出的"标准化论证框架文档"。该文档应包含：
- 核心命题（一句话表述）
- 论证线索（核心主张→前置论点→依据→反驳回应）
- 章节规划（初步的一级标题框架）

如输入文档缺少上述要素，标记为"数据接口不对齐"，要求环节2补充。

## 输出底线

- 不替作者写提纲。只审查已写提纲。
- 评分必须附带具体理由和提纲中的对应位置。
- 结构问题标注必须精确到提纲的哪个标题的什么问题。
- 修改建议必须可操作——不说"提纲需要调整"，说"第二章第二节与第三章的论证线索断裂，建议将X调整到Y位置"。
- 数据接口检查必须显式执行，不能默认对齐。
- **实务轨必须读取并消费线索卡**——检查6.6必须显式执行，提纲无对应章节=问题回应闭环不闭合。
